# GER Archive

Сайт на GitHub Pages: **https://mrhitrech.github.io/ger-archive/**. Репозиторий: [MrHitrech/ger-archive](https://github.com/MrHitrech/ger-archive).

Русскоязычный справочник **God Eater Resurrection**: связанные материалы, снаряжение, миссии, арагами и план крафта. React, TypeScript, Vite и Tailwind CSS. Сайт использует локальные JSON, без регистрации, backend или API для посетителя.

## Запуск

Требуется Node.js **24** (минимум 22.18 с поддержкой запуска TypeScript в тестах).

```sh
npm ci
npm run dev
```

Откройте адрес, выведенный Vite, обычно `http://127.0.0.1:5173/`. `predev` проверяет базу и подготавливает локальные данные приложения. После изменения файлов `data/` перезапустите dev-сервер.

В текущем Windows-окружении Node установлен, но его каталог может отсутствовать в PATH сеанса. Для PowerShell:

```powershell
$env:Path = 'C:\Program Files\nodejs;' + $env:Path
npm run dev
```

Не открывайте `dist/index.html` через `file://`: локальные JSON загружаются через HTTP.

## Проверки и сборка

```sh
npm test                 # проверки данных, импортера, поиска, сохранения и калькулятора
npm run build            # валидация данных, контроль копий, TypeScript, Vite → dist/
npm run preview          # предпросмотр готовой сборки
npm run test:browser     # сборка + сценарии Chrome/Chromium под /ger-archive/
```

Браузерные проверки используют установленный Chrome на стандартном Windows-пути. В другом окружении задайте `CHROME_PATH` или предварительно установите Chromium: `npx playwright install chromium`. Тесты открывают отдельный временный профиль и не используют личные вкладки. В ограниченном исполнителе Windows может потребоваться разрешение на запуск и завершение тестовых процессов.

`npm run data:check` проверяет JSON Schema, ID, межфайловые ссылки, дубликаты, ранги 1–14, операции создания/улучшения, циклы, положительные количества, вероятности 0–100 / `null`, источники, исходные английские названия и SHA-256 копий. Неподтверждённые факты не могут получить `verified` одной сменой статуса.

## Что работает

- Отдельные каталоги материалов, снаряжения, миссий и арагами; поиск RU/EN, альтернативные названия, `ё/е`, регистр и небольшие опечатки.
- Переходы **предмет → рецепт → материал → миссия → арагами** и обратные связи из материала в рецепты.
- Фильтры сложности 1–14 и испытаний, категорий, элементов, семейств и операций; визуальное дерево импортированных веток.
- Чёткое разделение создания и улучшения. В дереве переход к каждому узлу открывает его материалы, стоимость и характеристики.
- План из нескольких целей: отдельная операция или цепочка с нуля / имеющегося предшественника, количество, выбор альтернативного рецепта.
- Совместное использование предшественника только при явном выборе одного физического экземпляра. Несовместимые финальные ветки вызывают ошибку.
- Запасы вычитаются **после суммирования целей**: `max(0, нужно − есть)`; выполненные цели исключаются без автоматического расходования инвентаря.
- Избранное, недавние записи, три режима названий, локальное сохранение и экспорт/импорт резервной копии.
- Страница источников, отчёт о наполнении, неизвестные шансы и подробные свидетельства.
- Ленивые страницы и разделы JSON, локальный поисковый индекс, адаптивные таблицы и прокручиваемое дерево.

Рекомендации «самый быстрый фарм» не показываются: нет проверенных времён прохождения, количества наград и модели слотов. Большинство таблиц наград, пожирания и разрушения частей ещё отсутствует. Они не заменены данными Burst/GE2 или предположениями.

## GitHub Pages

Workflow `.github/workflows/pages.yml` запускает проверки и собирает сайт для PR. Push в `main` после успешных проверок публикует `dist/` в GitHub Pages. **Публикуется текущее состояние с его отметками, а не автоматически подтверждённая база.** Полноценный релиз требует работы с источниками и переводами, описанной выше.

1. Загрузите проект в выбранный GitHub-репозиторий с веткой `main`.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. Выполните push или запустите workflow вручную. URL появится в окружении `github-pages` после успешного deployment.

Публикация настроена для [MrHitrech/ger-archive](https://github.com/MrHitrech/ger-archive): push в `main` запускает проверки и обновляет сайт. Используется `HashRouter` и Vite `base: './'`; ассеты, JSON и прямые ссылки работают и в корне, и под `/repository/`. При необходимости абсолютный префикс задаётся переменной `VITE_BASE_PATH=/repository/`. GitHub Pages предоставляет HTTPS; при собственном домене включите Enforce HTTPS в настройках Pages.

Конфигурация публикации следует [документации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
