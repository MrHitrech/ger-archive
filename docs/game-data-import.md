# Импорт данных из установленной GER

Импорт читает локальную Steam-установку God Eater Resurrection (App ID 460870). Он работает отдельно от сборки сайта: для обычного запуска приложения игра не нужна.

## Выполненный импорт

16 ноября 2026 дополнен импорт фактов сборки **1412844**. В базе **616 материалов, 2 787 предметов снаряжения и 2 806 рецептов**. Среди материалов 615 сопоставлены с игровым ID; прежний `Elastomer` сохранён с нерешённым соответствием. Все существовавшие ID сайта сохранены.

Рецепты включают изготовление и улучшения оружия, огнестрельного оружия, щитов, модулей и одежды. Импортированы элементы всего снаряжения, полный перечень 363 миссий с 21 дополнительным этапом и 21 798 способов получения для 615 материалов: 5481 основная награда, 2221 бонус за время и выносливость, 3753 позиции раскола защиты, 3588 позиций пожирания, 6755 позиций сбора. Все миссии и этапы имеют русское имя. Для основных наград и поддержанных бонусов читаются проценты; для остальных способов сохраняются веса без объявления их подтверждёнными шансами. Добавлены «Небесный отец» (Heavenly Father, семейство 31) и тренировочная локация. Синтез пока не переносится в базу.

Исходные игровые архивы и полные описания остаются в игнорируемом `artifacts/`. В `data/evidence/` помещаются выбранные факты в JSON: ID, имена, категории, ранги, ингредиенты, количества, стоимость, поля элементов, позиции наград и исходные числа условий.

## Повторение

В PowerShell, из корня проекта:

```powershell
$env:Path = 'C:\Program Files\nodejs;' + $env:Path
npm run game:extract -- --game-dir 'G:\SteamLibrary\steamapps\common\GOD EATER RESURRECTION'
npm run game:import -- --sample --dry-run
npm run game:import -- --dry-run
```

Извлечение создаёт `artifacts/game-extract/`. Предварительный импорт сохраняет план в `artifacts/game-import/full/plan.json`; пробный режим — в `artifacts/game-import/sample/plan.json`. Он не меняет `data/`.

Изучите `factual_changes`, `blocking`, `validation_errors`, `issues` и сопоставления ID. Для применения используйте точный `plan_sha256`, полученный в предварительном запуске:

```powershell
npm run game:import -- --apply --expected-plan 'SHA_FROM_PREVIEW'
npm run data:check
npm test
npm run build
```

`SHA_FROM_PREVIEW` нужно заменить на выведенные 64 шестнадцатеричных символа. Изменение базы или источника после предварительного просмотра делает прежний план неприменимым. `--sample` предназначен только для предварительной проверки цепочки Knife P → Knife. Дату можно зафиксировать параметром `--checked-at YYYY-MM-DD`; по умолчанию используется дата Europe/Berlin.

Перед применением автоматически создаётся копия `data/` в `artifacts/game-import/backups/before-*/data/`. Каждый файл заменяется атомарно, но весь набор файлов не является одной транзакцией. При прерванном применении восстановите исходные файлы из указанной копии и повторите проверку.

## Что проверяется

- Заголовки и границы QPCK, PRES, BLZ4, KST и TR2; дублирующиеся ключи и соответствие числа строк.
- Приоритет `bin_patch.qpck` над исходными архивами. Если доступны несколько копий ресурса одного приоритета, сравнивается распакованное содержимое; противоречие останавливает извлечение.
- Размер и MD5 из заголовков BLZ4, SHA-256 распакованных ресурсов и промежуточных JSON.
- При импорте JSON повторно сопоставляется с декодированием сохранённого бинарного ресурса.
- Наличие результатов, предшественников и ингредиентов, положительные количества, категории и отсутствие циклов.
- Соответствие нормализованных рецептов выбранным фактам в свидетельствах и контрольным суммам источника.
- Сохранение старых ID. Новые ID зависят от App ID, игровой таблицы и ключа строки; перевод и номер сборки не входят в идентичность.

Повторный импорт той же выгрузки с той же датой не создаёт новых игровых записей и не изменяет существующие факты. Обычная сборка использует только сохранённые JSON и проверяет их без доступа к установленной игре.

## Сопоставления и обнаруженные различия

Точные имена и категории позволяют присоединить игровой ID к существующему ID сайта. Неоднозначное совпадение блокирует применение. Явные исключения находятся в [game-articles.json](../data/import-mappings/game-articles.json): `Wukong Armor+` и `King Armor+` сопоставлены с вариантами, в которых перед `+` есть пробел. Суффикс сохраняется; базовые материалы с вариантами `+` не объединяются. Старые имена добавлены в поисковые псевдонимы, русские редакционные варианты сохранены.

Строка улучшения **942** для **Dama de Ferro II** использует материал **10166 — Pixie Elastomer**. В старом рецепте был `Elastomer`; ссылка заменена на уже существующий ID Pixie Elastomer. Самостоятельная запись Elastomer сохранена с `missing_fields: native_identity`, поскольку её отдельное соответствие в игре не установлено.

Строка улучшения **1793** для **Koenig Schild** ссылается на отсутствующий базовый предмет **12777**. Она не импортирована как рабочий рецепт и находится в карантине.

## Что остаётся неизвестным

Наличие строки в рабочем ресурсе не подтверждает доступность предмета игроку. Очевидные тестовые имена и заполнители отклоняются; для остальных импортированных записей сохраняется `in_game_availability`.

Ранг предмета читается из каталога. Расположение поля сверено со всеми 51 предметами начального набора. `required_rank` в текущей модели хранит ранг результата, а не расшифровку сюжетного условия. Исходные условия открытия находятся в `unlock_conditions_raw` и остаются непроверенными. У новых предметов нерасшифрованные характеристики и навыки помечены как пропуски; отсутствие числа не превращается в нулевую характеристику.

KST улучшений содержит упакованные поля. Их структура проверена на всём наборе, но ручная сверка с экраном игры остаётся открытой. Поэтому импорт не назначает статус `verified` и не выдаёт автоматическую проверку за ручную.

Русские имена предметов декодируются отдельным кодеком `ger-ru-article-name-v1` из `scripts/lib/game-text.mjs`. Только для поля `ru/article.kst` значения 0x0B и 0x0C преобразуются добавлением 0x425 к кодовой точке, значения 0x0E–0x1F — добавлением 0x424. Прочие символы, включая CR, LF, табуляцию, латинские суффиксы и уже читаемый русский текст, сохраняются. Правило не применяется ко всем текстам и языкам.

Сырая выгрузка остаётся неизменной. Свидетельство нового имени содержит исходную строку, результат декодирования, версию кодека, игровой ID и SHA-256 русского ресурса. Валидатор проверяет декодирование и совпадение игрового ID с предметом сайта. Нераспознанные управляющие символы блокируют использование имени.

Запись перевода с `name_ru: null` считается пропуском и заполняется по игровому ID. Любое существующее непустое русское имя, его статус, источник, ссылки и редакционные псевдонимы сохраняются. Импорт не повышает статус до `verified` или `official`. Повторная обработка не дублирует переводы или свидетельства; исходные названия и суффиксы II, N, X, EX и + остаются доступными.

Кодеком имён предметов заполнены 3189 пропусков с сохранением всех 299 ранее заполненных переводов. Пример: ID 10874 (`ger-i-d0fd2f61e158`) → **Риголетто II**.

## Русские названия и сопоставления миссий

`bin/resconv_pc/data/Locale/exported/ru/mission.kst.blz` содержит те же 515 ID, что английская таблица. Название читается по указателю в смещении 292. Эти строки уже имеют обычную UTF-8 кодировку: кодек `ger-ru-mission-name-v1` сохраняет их без преобразования символов и отклоняет управляющие символы. Кодек упакованных имён предметов к миссиям не применяется. До импорта проверяется совпадение наборов ID и числовых наград EN/RU.

При первом сопоставлении добавлены 219 отсутствовавших русских имён с сохранением всех 3488 ранее заполненных названий, статусов, источников, ссылок и сведений о рецензентах. Затем добавлены ещё 14 миссий и их русские имена. Все 259 миссий каталога переведены; два оставшихся пропуска относятся к арагами. Например, редакционное имя Mayflies остаётся «Подёнки», хотя в русской таблице игры указана «Приманка».

В `data/import-mappings/game-missions.json` зафиксированы 11 исправлений: десять английских написаний и локация Angel's Ladder (Forgotten Carrier вместо прежней Wailing Plains). Среди написаний — `Tandall` → `Tandoor`, `Runway Tank` → `Runaway Tank`, `Soilder's Grave` → `Soldier's Grave`. Проверяются точный игровой ID, ранг и локация. ID сайта и русские редакционные имена сохраняются, прежние английские имена становятся поисковыми псевдонимами. Неточные совпадения в дальнейшем автоматически не принимаются.

## Элемент «Свет»

Внутренний ключ `divine` оставлен для совместимости ссылок и фильтров; русская подпись — **Свет**. Из `en/article.kst` читаются четыре знаковых 16-битных поля по смещениям 38, 40, 42, 44 в 76-байтовой записи: blaze, freeze, spark, divine. Нейтральное значение зависит от младшего байта категории:

| Категория                   | Нейтральное значение | Что попадает в фильтр                                            |
| --------------------------- | -------------------: | ---------------------------------------------------------------- |
| 14: холодное оружие         |                    0 | Значение > 0                                                     |
| 15: огнестрельное оружие    |                    3 | Усиленная стихия, значение > 3; значение 2 не является усилением |
| 16: щиты                    |                    2 | Усиленное сопротивление, значение > 2                            |
| 12, 13, 17: одежда и модули |                    0 | Прямого элемента нет; ненулевые значения отклоняются             |

Кодек `ger-article-elements-v1` проверяет категорию и допустимый диапазон, сохраняет сырые байты, значения, базовый уровень и смысл поля в отдельном свидетельстве. Исторические свидетельства названий не перезаписываются. «Свет» найден у 636 предметов; у Immunity Buckler исправлен пропуск четвёртого сопротивления в исходном наборе Wiki. Неизвестные общие характеристики и навыки этим не заполняются.

## Основные награды миссий и проценты

Источник — `bin/resconv_pc/data/Locale/exported/en/mission.kst.blz` из `bin.qpck` с учётом приоритета патча. Распакованный ресурс имеет SHA-256 `a3fc69dd2570253033418d4ccc55a61cba54305ea287a61aea4acedd403376f3`. В нём 515 строк по 312 байт. Кодек `ger-mission-rewards-v1` читает:

| Смещение в строке        | Поле                                                                  |
| ------------------------ | --------------------------------------------------------------------- |
| 0, uint16 LE             | Игровой ключ миссии                                                   |
| 6, uint8                 | Числовой ранг                                                         |
| 28 + 2 × slot, int16 LE  | ID награды, 32 позиции; отрицательные значения используются для денег |
| 92 + slot, uint8         | Процент этой позиции                                                  |
| 124 + slot, uint8        | Код условия                                                           |
| 292, uint32 LE           | Указатель на английское название                                      |
| 300, 304, 308, uint32 LE | Указатели на контекст, в том числе локацию                            |

После явных исправлений сопоставление требует точного английского названия, числового ранга и локации. Несколько подходящих игровых строк принимаются только при одинаковых таблицах наград; сохраняется максимальный ключ и список эквивалентных ключей. Сопоставлены все 384 записи миссий и этапов каталога. Прежние ID сохраняются; ID добавляемых миссий зависят от App ID и игрового ключа.

## Полный перечень миссий сложностей 1–14

Первый список миссий был ограничен неполной копией Wiki. Политика версии 2 в `data/import-mappings/game-mission-catalogue.json` фиксирует все **515 производственных строк `mission.kst`** сборки 1412844: после объединения сюжетных и свободных копий остаются **384 ключа**. Из них 363 самостоятельные миссии и 21 дочерний этап выживания. После предыдущего дополнения сложностей 3–4 добавлены ещё 125 записей, включая Drosera («Росянка», 20082), Tutorial 1/2 (20016/20017) и Practice Tutorial (20156). Все прежние ID, имена, локации и редакционные переводы сохранены.

Обычные задания, обучения и испытания по сложностям 1–14: **7, 18, 24, 21, 23, 28, 28, 22, 23, 21, 12, 11, 14, 81**. Срочные задания имеют нативный код 3, дополнительные — 4; по умолчанию в каталоге показывается основной список с кодом 0. Фильтр «Все типы» включает 15 срочных и 15 дополнительных миссий. Сложность испытаний приведена к числу 14 без замены ID. Старый фильтр `rank=challenge` сохраняет смысл отбора испытаний.

Кодек `ger-mission-catalogue-v1` использует ранг из смещения 6 и код типа 0 из смещения 4 записи `mission.kst`. Записи 48 и 20048, например, относятся к одной базовой миссии Rusted Edge. Такие сюжетные и свободные варианты объединяются только при совпадающих имени, локации и таблице наград. Выбирается максимальный ключ, список эквивалентных ID сохраняется. Срочные Midpoint (20377) и Triple Cross (20378), имеющие код типа 3, не входят в обычные количества 24 и 21.

Новая миссия требует русского имени, рабочего контейнера, однозначной локации и подтверждённых таблицами появления целей. Описание читается по указателю в смещении 296, лимит времени — как uint16 LE в смещении 2. Эти поля и версия `ger-mission-catalogue-v2` сохраняются в свидетельстве `catalogue`; валидатор проверяет описание, время, тип и доказательства состава врагов. Ранее опубликованные свидетельства v1 сохраняются. Мишени `Move Target` в трёх обучениях отдельно разрешены по семейству и модели; они не становятся Ogretail или Vajra и не дают фиктивной добычи. Training Grounds / «Тренировочный центр» подтверждены EN/RU контекстом миссии и кодом локации 10. Небоевой Today's Fortune (20409) разрешён отдельно по описанию автоматического завершения и таблице цели без появления врагов.

13 цепочек выживания определены по `Survival Phase i/n` в контексте, а не по соседству ключей. У Spiritus ключи идут в обратном порядке: 20432, 20431, 20430. `parent_mission_id`, `phase_index`, `phase_count` связывают этапы; дочерние записи сохраняют собственные локации, состав врагов и добычу. Каталог считает и показывает корневую миссию, её карточка даёт переходы на все этапы. Полнота перечня, все 14 счётчиков, цепочки и сохранность переводов проверяются тестами. `coverage.missions.total` и `universe_total` равны 363; `records_total` — 384, `stage_records` — 21. Сюжетность, условия открытия, неизвестные условия наград и ручная проверка не объявляются завершёнными. Повторный импорт не добавляет дубли.

Основные награды сохраняют кодек `ger-mission-rewards-v1`; поддержанные условные награды используют `ger-mission-rewards-v2` и отдельный снимок. Импортируются материалы с установленным игровым ID и ненулевым процентом:

| Код условия | Значение                        | Категория             |
| ----------- | ------------------------------- | --------------------- |
| 0           | Automatic                       | Автоматически         |
| 2           | Завершить менее чем за 3 минуты | За выполнение условий |
| 3           | Завершить менее чем за 5 минут  | За выполнение условий |
| 4           | Завершить менее чем за 10 минут | За выполнение условий |
| 5           | Завершить с Endurance 30+       | За выполнение условий |

Соответствия проверены по ограниченным таблицам наград [GER](https://godeater.fandom.com/wiki/Missions/God_Eater_Resurrection) и [сюжетных миссий GER](https://godeater.fandom.com/wiki/Missions/God_Eater_Resurrection_-_Story_Missions); ручная проверка в игре остаётся открытой. Эти коды нельзя приравнивать к порядку строк в `game_text.tr2`. Деньги, расходники и остальные коды пропускаются. Шесть прежних бонусных ID переиспользованы; старые ссылки сохранены, проценты не изменены. Бонус за общее число расколов не подменяет награду за конкретную часть тела.

Для «Хвоста дьявола» автоматически прочитанные значения совпадают с известными строками Wiki. Для Impure Grease теперь видны отдельные позиции 100% и 33%. Для Pixie Thorn в Mayflies сохраняются **две позиции по 25%**, без превращения в общий шанс 50% или предположения о независимости. Поле количества остаётся `null`. Это проценты из таблицы, а не экспериментальная оценка выпадения за прохождение.

Идентичность награды включает игровой ключ миссии и номер позиции (0–31), а не её название, перевод или сборку. Прежние ID способов получения переиспользуются для соответствующей позиции. Каждая строка хранит `game_origin.slot`, исходный ресурс, SHA-256, версию декодера, сырую запись и ссылки на свидетельства. Валидатор повторно читает проценты и ID из сохранённых байтов; подмена шанса, материала, позиции или известного количества блокирует публикацию.

## Раскол защиты, пожирание и сбор

`data/import-mappings/game-mission-resources.json` содержит 384 проверенных контейнера `bin/resconv_pc/src/god_g000_Mission/<folder>.res`. Из каждого извлекаются EN/RU параметры врагов и частей, `en_mat`, `dig`, `quest_flow`, `enemy_entry_table`. Полная выгрузка содержит 3081 ресурс. Приоритет патча и сравнение нескольких активных копий применяются также к этим таблицам.

- **`en_trig_group.tr2`** — раскол защиты конкретной части. Поля `en_trig_group_enemy_class_id`, `en_trig_group_display_name`, `en_trig_group_mat_id_array`, `en_trig_group_weight_group_id_array`. Русское название части присоединяется по ID из RU-таблицы; сверяются класс врага, массивы материалов и веса. `en_trig_group_break_count` сохраняется как исходное число и не интерпретируется как требование сломать столько частей.
- **`en_mat.tr2`** — основная таблица материалов врага в миссии: `en_mat_enemy_class_id`, `en_mat_article_id`, `en_mat_wait`. Категория получения — пожирание поверженного арагами; точная механика выбора и модификаторы остаются непроверенными. Дополнительный пул `en_base.append_material` не подставляется вместо него: обнаружено 381 различие, включая отсутствующие и отличающиеся наборы. Это отдельный вопрос аудита.
- **`dig.tr2`** — сбор на карте: `dig_volume_name`, `dig_id_array`, `dig_weight_array`. Позиции разных точек не объединяются.
- **`en_base.tr2`** — названия и семейство арагами, имя ресурса модели. Сопоставления 53 семейств с ID сайта находятся в `data/import-mappings/game-aragami.json`. Варианты огня, льда и молнии различаются по семейству и ресурсу, а не только по одинаковому отображаемому имени. Heavenly Father (31) не объединяется с Dyaus Pita (142).
- **`quest_flow.tr2` и `enemy_entry_table.tr2`** — проверка появления класса в миссии. Класс должен реально присутствовать в задании с положительным количеством либо в таблице случайного появления с положительным весом. Неиспользуемые классы, например служебный Amor, не становятся источниками добычи.

Локализованные параметры находятся, например, по пути `data/Locale/exported/en/data-GameData-mission-031_Temple_NormalRank02-db-enemy-Tr2-en_trig_group.tr2`. Для хвоста Kongou в этой миссии сохранены две позиции с весами 18 и 82; для торса — 50 и 50, для лица — 100. Это награды отдельных частей, а не общий бонус за несколько расколов.

Веса не всегда дают 100. В исследованном наборе встречаются суммы 95–102; у одной точки сбора три веса по 33 дают 99. Поэтому `drop_rate` остаётся `null`, исходные `pool_weight` и `pool_total_weight` сохраняются, а интерфейс отдельно показывает их математическую долю. Доля веса не объявляется вероятностью в игре. Нулевые и отрицательные веса не превращаются в награды, несовпадающие массивы блокируют импорт. Количество остаётся неизвестным.

Для таблиц миссий декодируются только нужные именованные столбцы. Остальные ячейки проверяются по границам без попытки интерпретировать неиспользуемые служебные строки как UTF-8: некоторые `ASCII` значения таблицы появления врагов имеют другую кодировку. Снимки содержат выбранные поля, игровые ключи, версии декодеров и SHA-256 полных бинарных ресурсов. Валидатор проверяет часть, вариант арагами, появление класса, полный пул весов и соответствие материала; изменение веса или превращение его в точный процент блокирует публикацию.

Полные исследовательские пути и архивные хеши локально доступны в `artifacts/game-research/path-map.json`, индекс таблиц — в `data.qpck.tables.json` рядом. Тестовые и устаревшие каталоги не добавляются автоматически. Остаются открытыми неизвестные коды условий `mission.kst`, дополнительный пул `en_base`, выбор наград по весам и игровые модификаторы. У одного материала текущего каталога (Elastomer) способ получения ещё не установлен.

Например, в `data.qpck` найдены `data/GameData/mission/024_Building_NormalRank01/db/enemy/Tr2/en_mat.tr2` (хеш пути `eab7c04c67dcf207`) и `data/GameData/mission/024_Building_NormalRank01/db/dig/Tr2/dig.tr2` (`c20e06a119b68409`). Номер каталога не следует автоматически приравнивать к полному ключу строки `mission.kst`: ключи вариантов могут быть больше 20000.

## Файлы аудита

- `data/sources.json` — сборка, архивы, пути ресурсов, SHA-256 и способ получения `game_files`.
- `data/evidence/claims.json` и `data/evidence/game-*.json` — выбранные факты и их контрольные суммы.
- `data/reports/game-id-map.json` — соответствия игровых ID и ID сайта.
- `data/reports/game-import.json` — отчёт применённого импорта.
- `data/quarantine.json` — нерешённые вопросы.
- `artifacts/game-extract/manifest.json` — воспроизводимая локальная выгрузка ресурсов.

Реализация читателей написана в проекте. Для исследования форматов использовались первичные материалы [qpckEater](https://github.com/mhvuze/qpckEater) и [GECV](https://github.com/HaoJun0823/GECV); сторонние распаковщики не запускаются.
