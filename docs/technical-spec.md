# Техническое задание
## God Eater Resurrection — русскоязычная база предметов, материалов и крафта

**Версия ТЗ:** 1.0  
**Тип проекта:** Игровой веб-справочник  
**Платформа размещения:** GitHub Pages  
**Основной язык:** Русский  
**Дополнительный язык:** Английский  
**Игра:** God Eater Resurrection (не God Eater Burst и не God Eater 2)

---

## 1. Цель проекта

Разработать бесплатный русскоязычный веб-сайт, позволяющий игрокам God Eater Resurrection быстро находить материалы, рецепты крафта, улучшения экипировки и миссии, в которых можно получить необходимые ресурсы.

Сайт должен отвечать на три основных вопроса:

1. Где найти конкретный материал?
2. Какие материалы необходимы для создания или улучшения предмета?
3. В каких миссиях выгоднее всего добывать необходимые материалы?

**Главная особенность:** пользователь должен иметь возможность искать предметы как по русскому, так и по английскому названию, даже если информация первоначально была получена из англоязычной базы.

Сайт должен работать без регистрации, собственного сервера, платного API и постоянного подключения к сторонним сайтам.

## 2. Технологии

### 2.1. Основной стек

- React + TypeScript — интерфейс и логика.
- Vite — сборка сайта.
- Tailwind CSS — оформление.
- JSON — хранение игровых данных.
- localStorage — сохранение настроек, избранного и прогресса пользователя.
- GitHub — хранение кода и базы.
- GitHub Actions — автоматическая сборка и публикация.
- GitHub Pages — бесплатный хостинг.

Использовать клиентскую архитектуру без собственного backend.

### 2.2. Технические ограничения

- Все основные функции должны работать после загрузки локальных JSON-файлов.
- Нельзя делать работоспособность сайта зависимой от доступности Fandom или сторонних API.
- Не использовать платные сервисы.
- Не требовать от пользователя аккаунта.
- Сайт должен работать на компьютерах, планшетах и смартфонах.
- Навигация должна корректно работать по адресу `https://username.github.io/repository/`.
- Для маршрутизации использовать HashRouter либо другую полностью совместимую с GitHub Pages систему.
- Настроить Vite `base` с учётом имени репозитория.
- Обеспечить работу через HTTPS.

## 3. Структура сайта

В главном меню должны находиться следующие разделы:

| Раздел | Назначение |
|---|---|
| Главная | Универсальный поиск и быстрый доступ |
| Материалы | Поиск ресурсов и способов добычи |

## 4. Поиск материалов

### 4.1. Каталог

Создать каталог всех доступных материалов, для которых удалось получить подтверждённую информацию именно по God Eater Resurrection.

Каждый материал должен иметь отдельную страницу.

Каталог должен содержать:

- Название на русском.
- Название на английском.
- Категорию материала.
- Диапазон сложностей, на которых он доступен.
- Возможные источники получения.
- Иконку, если есть изображение с разрешением на использование.

### 4.2. Поисковая строка

Поддерживать:

- Русские названия.
- Английские названия.
- Частичное совпадение.
- Поиск без учёта регистра и буквы «ё».
- Поиск по альтернативным переводам.
- Нечёткий поиск с исправлением небольших опечаток.
- Подсказки при вводе.

Пример:

Игрок вводит «Пепельное крыло» или `Ashen Wing`.

Система должна находить один и тот же материал по общему уникальному идентификатору.

### 4.3. Карточка материала

Страница материала должна включать:

**Основные сведения**
- Русское название.
- Оригинальное английское название.
- Категория.
- Краткое описание, если оно существует в источнике.
- Доступные уровни сложности.

**Где получить**
- Название миссии на русском и английском.
- Уровень сложности миссии.
- Арагами, встречающиеся в миссии.
- Способ получения материала.
- Вероятность получения.
- Дополнительные условия получения.

Возможные способы получения:

1. Автоматическая награда миссии.
2. Дополнительная награда миссии.
3. Пожирание арагами.
4. Разрушение определённой части тела арагами.
5. Сбор на локации.
6. Покупка у торговца.
7. Обмен или синтез.

Если шанс получения не подтверждён, отображать «Шанс неизвестен», а не придумывать процент.

**Для чего нужен**
- Список оружия, в рецептах которого применяется материал.
- Список щитов.
- Список других предметов.
- Количество материала, необходимое в каждом рецепте.

Каждая строка должна вести на соответствующую страницу предмета или миссии.

### 4.4. Сортировка способов получения

Предусмотреть сортировку по:

- Сложности миссии.
- Вероятности получения.
- Способу получения.
- Названию миссии.

Если данные позволяют, добавить рекомендацию «Лучший способ фарма».

При выборе лучшего способа учитывать подтверждённую вероятность, условия получения и сложность. Если нет достаточных данных, рекомендацию не показывать.

Не выдавать миссию с самым высоким процентом за объективно самую быструю без информации о времени прохождения.

## 5. Раздел «Крафт»

### 5.1. Назначение

Раздел предназначен для поиска всех создаваемых или улучшаемых предметов.

Основные категории:

- Короткие клинки.
- Длинные клинки.
- Тяжёлые клинки.
- Ускоряющие молоты.
- Зарядные копья.
- Косы.
- Огнестрельное оружие по его внутриигровым типам.
- Щиты по типам.
- Улучшения и дополнительные модули.
- Расходуемые предметы, имеющие рецепты.
- Другие категории крафта, подтверждённые игровой базой.

Для каждой категории создать отдельный фильтр.

### 5.2. Поиск предмета

Поиск должен работать по русскому, английскому и альтернативному названию.

Предусмотреть фильтры:

- Тип предмета.
- Ранг.
- Элемент.
- Наличие рецепта.
- Возможность улучшения.
- Семейство оружия.

### 5.3. Страница предмета

Отображать:

- Название на русском.
- Английское название.
- Тип предмета.
- Ранг.
- Характеристики и свойства, подтверждённые источниками.
- Стоимость создания в FC.
- Полный список необходимых материалов.
- Рецепты создания и улучшения.
- Предыдущее и следующее улучшение.
- Ссылки на источники данных.

Материалы рецепта должны быть кликабельными.

При нажатии на материал открывается его страница со списком миссий для добычи.

### 5.4. Дерево улучшений

Реализовать визуальное дерево развития оружия и других улучшаемых предметов.

Показывать:

- Исходный предмет.
- Следующие улучшения.
- Альтернативные ветки.
- Необходимые материалы.
- Стоимость каждого улучшения.
- Итоговые характеристики.

Важно правильно разделять создание предмета с нуля и улучшение уже существующего предмета.

Не объединять рецепты разных веток и разных игровых версий.

## 6. Калькулятор крафта

Дополнительная функция, непосредственно связанная с разделом «Крафт».

### 6.1. Выбор цели

Игрок выбирает предмет, который хочет изготовить.

Система показывает полный список материалов, необходимых для выбранного рецепта.

### 6.2. Учёт имеющихся ресурсов

Для каждого материала добавить поле «Уже есть».

Пример:

| Материал | Нужно | Есть | Осталось |
|---|---:|---:|---:|
| Материал A | 5 | 2 | 3 |
| Материал B | 3 | 0 | 3 |
| Материал C | 2 | 2 | 0 |

Все значения должны рассчитываться автоматически.

Формула:

**Осталось = max(0, Нужно − Есть)**

### 6.3. Список фарма

Для недостающих материалов система должна автоматически создавать перечень доступных миссий.

Нажатие на материал открывает информацию о способах его получения.

При наличии достоверных данных отображать более удобные варианты добычи.

### 6.4. Несколько целей

Предусмотреть возможность добавления нескольких предметов в список крафта.

Система должна суммировать необходимые материалы и учитывать запасы игрока.

Общие предшествующие улучшения не должны учитываться дважды, если цели используют один и тот же экземпляр предмета и пользователь явно указал такую цепочку.

Должна существовать возможность удалить цель, выбрать другую ветку улучшения или сбросить расчёт.

### 6.5. Сохранение

Использовать localStorage для сохранения:

- Выбранных целей.
- Количества имеющихся материалов.
- Избранных рецептов.
- Отмеченных как выполненные целей.

## 7. База миссий

Создать отдельную базу миссий God Eater Resurrection.

Для каждой миссии хранить:

- Уникальный ID.
- Название на английском.
- Переведённое название.
- Уровень сложности.
- Тип задания.
- Локацию.
- Основные цели.
- Арагами.
- Таблицу наград.
- Условия получения наград.
- Вероятности выпадения, если известны.
- Ссылку на источник.

Обеспечить поддержку всех уровней сложности игры, включая высокоуровневые задания, вплоть до 14.

Предусмотреть фильтрацию по сложности, противнику, материалу и типу миссии.

На странице миссии должна быть таблица наград, где каждый материал является ссылкой.

Если миссии обладают одинаковыми названиями или дополнительными вариантами, хранить их отдельно по уникальным ID.

## 8. База арагами

Создать каталог противников.

Для каждого арагами предусмотреть:

- Русское и английское название.
- Тип или разновидность.
- Доступные уровни сложности.
- Материалы, получаемые с противника.
- Таблицу вероятностей, если она подтверждена.
- Части тела, которые можно разрушить.
- Связанные с разрушением материалы и условия.
- Миссии, в которых появляется арагами.

Отдельно учитывать различные разновидности арагами.

Не объединять обычные, падшие и элементальные варианты, если их наборы добычи отличаются.

## 9. Перевод на русский язык

### 9.1. Основное требование

**Весь пользовательский интерфейс и игровые данные должны отображаться на русском языке по умолчанию.**

Переводу подлежат:

- Названия материалов.
- Названия оружия и экипировки.
- Названия миссий.
- Названия локаций.
- Названия арагами.
- Типы предметов.
- Характеристики.
- Названия элементов.
- Условия получения ресурсов.
- Способы добычи.
- Текст интерфейса.

При этом оригинальные английские названия должны сохраняться в базе данных.

### 9.2. Приоритет перевода

Использовать следующую последовательность:

1. Официальное русское название из локализации God Eater Resurrection, если оно подтверждено.
2. Название из русскоязычной God Eater Wiki при отсутствии подтверждённого официального варианта.
3. Проверенный перевод, созданный специально для проекта.
4. Английское название, если корректный перевод пока отсутствует.

**Запрещается автоматически выдавать машинный перевод за официальное название.**

### 9.3. Словарь переводов

Создать отдельный словарь локализации.

Каждая запись должна содержать:

- Уникальный ID.
- Английское название.
- Русское название.
- Альтернативные названия.
- Источник перевода.
- Статус проверки перевода.

Использовать три статуса:

- `official` — официальный подтверждённый перевод.
- `verified` — проверенный неофициальный перевод.
- `unverified` — временный вариант, требующий проверки.

Название должно быть привязано к уникальному ID, а не выступать идентификатором само по себе.

### 9.4. Отображение названий

По умолчанию выводить:

**Пепельное крыло (Ashen Wing)**

Если перевод отсутствует:

**Ashen Wing — перевод не найден**

Пользователь должен иметь возможность переключить отображение:

- Русский + английский.
- Только русский, если перевод доступен.
- Только английский.

Настройки сохраняются в браузере.

### 9.5. Точность названий

Особое внимание уделить материалам с похожими названиями и разными рангами.

Не объединять разные материалы из-за сходного перевода.

Например, предметы с окончаниями `+`, `II`, `EX` и другими игровыми обозначениями должны сохранять свои отличия.

При импорте проверять, что перевод не приводит к ошибочному объединению записей.

### 9.6. Автоматизация перевода

Предусмотреть отдельный скрипт для подготовки переводов новых записей.

При импорте новых материалов:

1. Проверить существование перевода в словаре.
2. Попробовать найти подтверждённый русский аналог.
3. Если перевод не найден, добавить запись в список на проверку.
4. Не перезаписывать ранее проверенные переводы.
5. После подтверждения обновить локализованные данные.

Машинный перевод может использоваться как предварительная подсказка при подготовке базы, но не как обязательный онлайн-сервис для посетителей.

## 11. Структура базы данных

Все игровые данные хранить в локальных JSON-файлах.

Предлагаемая структура:

- `data/materials.json` — материалы.
- `data/items.json` — создаваемые предметы и экипировка.
- `data/recipes.json` — рецепты создания и улучшения.
- `data/missions.json` — миссии.
- `data/aragami.json` — противники.
- `data/drop-sources.json` — способы получения материалов.
- `data/translations/ru.json` — русские переводы.
- `data/translations/en.json` — оригинальные названия и английский текст.
- `data/sources.json` — происхождение информации.

### 11.1. Структура материала

Каждый материал должен содержать:

| Поле | Назначение |
|---|---|
| id | Уникальный идентификатор |
| name_en | Английское название |
| name_ru | Русское название |
| aliases | Альтернативные названия |
| category | Категория |
| ranks | Доступные ранги |
| sources | Идентификаторы способов получения |
| used_in | Связанные рецепты |
| references | Ссылки на первоисточники |

### 11.2. Структура источника добычи

Хранить отдельную запись для каждого сочетания материала и способа получения.

Поля:

- `id`
- `material_id`
- `mission_id`
- `aragami_id`
- `location_id`
- `method`
- `condition`
- `drop_rate`
- `source_url`
- `verification_status`

Вероятность хранить числом от 0 до 100 либо `null`.

Отсутствующее значение не должно интерпретироваться как 0%.

### 11.3. Структура рецепта

Каждый рецепт должен содержать:

- ID рецепта.
- ID создаваемого предмета.
- Тип операции: создание или улучшение.
- ID исходного предмета для улучшения, если применимо.
- Список материалов с количеством.
- Стоимость в FC.
- Необходимый ранг.
- Ссылки на источники.

Поддерживать несколько альтернативных рецептов одного предмета.

### 11.4. Связи данных

Все связи реализовать по ID:

- Материал → источники добычи.
- Материал → рецепты.
- Рецепт → готовый предмет.
- Предмет → дерево улучшений.
- Миссия → арагами.
- Миссия → награды.
- Арагами → материалы.

По этим связям должен работать обратный поиск без дублирования основной информации.

## 12. Импорт и обновление базы

Создать отдельный инструментарий наполнения базы.

Требования:

1. Поддерживать импорт информации из проверенных внешних источников.

Парсинг и обработку выполнять в процессе подготовки базы, локально либо через отдельные GitHub Actions, но не при каждом посещении сайта.

Необходимо учитывать ограничения сайтов-источников: автоматический сбор применять только тогда, когда он разрешён, и не пытаться обходить технические ограничения доступа.
